# Product Canvas：备份、恢复与第三方提供方密钥操作

第三方图像提供方的凭据不存明文。自建连接的凭据只会以
`fernet:v1:<token>` 写入 SQLite；解密所需的 `CANVAS_PROVIDER_SECRET_KEY`
只存在于受控部署环境中，绝不能写入项目、导出包、浏览器、本仓库或日志。

## 一致备份窗口

在停止接受新的 Canvas 付费生成并等待正在写入的任务完成后，于同一个维护
窗口备份以下三项：

1. 应用 SQLite 数据库（使用 SQLite 的在线备份或在服务停写后复制，而不是
   只复制 WAL 中的任意一个文件）。
2. `data/canvas_projects/`（或 `CANVAS_DATA_DIR` 指向的整个项目根目录），保留
   文件层级和访问控制。
3. 对应部署环境中的 `CANVAS_PROVIDER_SECRET_KEY`，通过批准的密钥管理系统备份
   或恢复；不要把它附在 SQLite 或文件归档中。

`data/models/rembg/` 是可重新下载的模型缓存，不是恢复必需数据。恢复后可重新
构建它，但不能把该缓存替代项目资产备份。

## 恢复检查表

在开放任何付费调用前：

1. 将数据库、`data/canvas_projects/` 和同一把 `CANVAS_PROVIDER_SECRET_KEY`
   恢复到隔离环境；确认项目根目录及每个相对资产路径仍在其项目目录内。
2. 对每类资产抽样重新计算 SHA-256，并确认数据库记录的 SHA、字节数、相对路径
   和文件解析结果一致；不要通过软链接或绝对路径绕过包含关系。
3. 对每个已配置第三方 Provider 执行非计费的连接配置测试，确认密文可以 decrypt
   成预期字段。解密失败时保留原密文取证并软禁用该 Provider；不要覆盖或重置它。
4. 验证内置 Provider 的环境凭据仍由部署端管理，且公网/私网主机白名单、HTTP
   开关、超时和大小上限符合当前安全策略。
5. 通过项目浏览、只读结果版本和一个受控的 paid 访问锁检查后，才重新开启付费
   生成。若 Provider 只能通过生成验证，先显示可能收费并取得明确批准。

本版本没有在线主密钥轮换接口。轮换必须通过新的维护窗口：停止付费任务、备份、
用新密钥离线重加密所有可解密凭据、验证恢复检查表，再切换运行环境。
