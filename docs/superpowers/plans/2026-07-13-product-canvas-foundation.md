# Product Canvas Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在现有 `/app` 工具面中加入独立的产品视觉画布，交付可持久化的项目/SKU/语义状态、无限画布交互、完整套图与高级节点共用状态、自动保存、版本冲突和持久事件骨架。

**Architecture:** FastAPI 继续负责页面与领域 API；SQLite 保存规范化项目、SKU、资产元数据和事件；Vite + TypeScript + Fabric.js 构建独立前端。`ProjectStore` 是业务状态唯一权威，`CanvasAdapter` 是 Fabric 唯一边界，服务端只保存语义与归一化布局，绝不保存 Fabric JSON。

**Tech Stack:** FastAPI, SQLAlchemy, Pydantic, SQLite, Jinja2, TypeScript 7.0.2, Vite 8.1.4, Fabric.js 7.4.0, Vitest 4.1.10, jsdom 29.1.1, Playwright.

## Global Constraints

- 先阅读设计文档 `docs/superpowers/specs/2026-07-13-product-image-infinite-canvas-design.md`；本计划只实现交付切片 1。
- 保留工作区已有改动；每次提交只暂存本计划列出的画布文件。
- `/app` 只新增“产品视觉画布”入口，不重排现有工具，不把画布代码写入 `static/js/inspiration.js`。
- 项目状态不得包含 Fabric JSON、Base64、密钥、临时第三方 URL、服务器绝对路径或未校验外链。
- Pydantic 写入模型统一 `extra="forbid"`；项目状态请求体上限 5 MB，提示词 4,000 字符，节点 500、连线 1,000、文字 100,000 字符。
- 项目状态 wire JSON 统一 camelCase；Python 内部字段使用显式 alias，读取后统一 `model_dump(by_alias=True)`。TypeScript 与 Pydantic 共用同一组 round-trip JSON 向量。
- 新项目的主图、SKU 图、详情图均未选中；不能用默认选择代替用户决策。
- SKU 表是 SKU 名称、引用素材、提示词和配置的唯一权威；语义图只保存 SKU ID。
- 每个可观察行为先写失败测试，再写最小实现；测试禁止真实网络和付费模型。
- 固定生产构建输出 `static/canvas/canvas.js` 与 `static/canvas/canvas.css` 并提交；Python 单独启动时页面必须可用。

Historical Generation snapshots do not block because the SKU row remains. DELETE then soft-deletes the SKU, clears its live reference-asset FK, increments the project revision and preserves the ID/name/config row for history; Generation inputs independently retain their asset FKs. Active list APIs exclude the soft-deleted SKU.
- Every Asset ID in semantic/layout state, including an output board’s selected result asset ID, must belong to the same project; immutable version history is derived from Generation results and is not duplicated in project JSON.
